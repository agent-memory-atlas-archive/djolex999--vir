You are grading whether a note from a developer's personal knowledge vault is relevant to a search query. The vault holds notes distilled from past coding sessions: patterns, gotchas, decisions, and tool insights. The query is what a developer (or their coding agent) typed before starting a task, hoping to find prior learnings.

Grade each candidate note on this scale:

2 — Directly answers the query. A developer who typed this query would read this note and get what they were looking for: the specific problem, decision, pattern or error the query names is the note's subject or one of its main lessons.

1 — Partially relevant. The note touches the query's topic, shares its context, or would be a useful adjacent read, but a developer would still need to look elsewhere for what they actually asked. Includes: same tool or library but a different problem; same problem in a clearly different setting; a general principle the query is a specific case of.

0 — Not relevant. The note would not help with the query. Sharing a word, a project name, or a programming language with the query is not relevance. If the query is about something the vault plainly does not cover (cooking, geography, a technology never mentioned), grade 0 even for the closest note.

Rules:
- Grade each note independently. Do not spread grades to make the set look balanced; it is normal for every candidate to be 0, or for several to be 2.
- Grade on the note's content, not its title. A promising title over unrelated content is 0.
- Judge from the excerpt shown. Do not assume content beyond it.
- When torn between two grades, pick the lower one.
